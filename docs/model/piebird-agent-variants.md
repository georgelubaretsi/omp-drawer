## 1. The session starts

### The tool: `agent_variant_setup` in omp, in every prompt

```text
Set up a temporary OMP agent variant when the user asks to launch, run, or delegate work with a particular model, provider, cost constraint, or reasoning level. Infer the source agent from intent: designer for UI/UX, reviewer for correctness review, security-reviewer for security, librarian for external research, scout for repository exploration, sonic only for explicitly mechanical work, otherwise task. This tool configures the variant but does not launch it. Project scope is mandatory unless the user explicitly requests global scope. Never claim project-write approval unless repository instructions were checked. Models from a provider signed in with OAuth (a subscription login) are subscription routes; paid per-token selectors (API keys with a price) require explicit user approval.
```

| Argument | What the model reads |
| --- | --- |
| `sourceAgent` | Existing OMP agent behavior to preserve; omit only for generic task work. |
| `modelQuery` | Natural model request or exact selector, such as Kimi K3 or ox-alpha. |
| `thinking` | Requested thinking level; omit to preserve source-agent behavior. |
| `targetName` | Optional temporary agent name. |
| `scope` | Where the variant goes: project (the default), or global when the user asks for it. |
| `subscriptionProviders` | Provider ids the user explicitly identified as subscription-backed; providers signed in with OAuth count as subscriptions already. |
| `approvedPaidSelectors` | Exact paid selectors explicitly approved by the user for this setup. |
| `includePaidFallbacks` | Whether the user requested paid fallbacks in addition to free/subscription routes. |
| `projectWriteApproved` | True only after repository instructions and status permit the target .omp writes. |
| `replaceTemporary` | Update an existing temporary variant with the same name. |

## 2. Before the project's instructions are checked

The agent calls `agent_variant_setup` with `{"modelQuery":"ox alpha"}`.

### The tool's result in omp

```text
Project write not approved. Check that the repository's instructions allow writing .omp agent configuration (`git ls-files -- '*AGENTS.md' '*CLAUDE.md'` lists them; none means nothing forbids it), and that .omp has no changes not committed (`git status --short -- .omp`): if it has, tell the user and stop, since the tool won't write over them. Otherwise call agent_variant_setup again with projectWriteApproved: true. Don't edit .omp files yourself or move the variant to another scope to get around this.
```

From [`blocked`](../../plugins/piebird-agent-variants/core/model.ftl#L17).
