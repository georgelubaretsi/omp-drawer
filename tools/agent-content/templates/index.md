# What agents receive from the omp plugins

One page per plugin (workflow's skill has a second one). On each page, **a tinted box, or a cell under "What the agent gets", is exactly what the agent receives**; everything else is a note on when it's sent.

| Plugin | What it sends |
| --- | --- |
| [sessions](sessions.md) | The `session_read` tool (description, results, errors) and the agent's own session line |
| [threads](threads.md) | The open-threads list, the `threads` rule and the `threads` skill |
| [tern](tern.md) | The `tern_lua` tool (description, results, errors), the `tern-agents` rule and the `tern` skill |
| [agent-variants](agent-variants.md) | The `agent_variant_setup` tool (description, results, errors) and the variant's description |
| [workflow](workflow.md) | Rules on how to work, and the `failure-classes` skill ([its page](workflow-skills.md)) |
| [kagi](kagi.md) | The kagi MCP server's tools (named, not shown: their text comes from the kagi CLI), the `web-search` rule and the `kagi` skill |

Generated by `bun tools/agent-content.ts` (`just build`) from made-up sample data run through each plugin's own code; `just check` fails when a page is out of date. Don't edit these pages: their wording is in `tools/agent-content/templates/`.
